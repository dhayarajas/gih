Overview

This guide provides step-by-step instructions for running Ghost Identity Hunter using Docker containers for isolated, reproducible OSINT investigations.

Prerequisites

  • Docker Compose (included with Docker Desktop)

Step 2: Clone and Configure the Project

2.1 Clone the Repository

git clone https://github.com/dhayarajas/gih.git
cd cscd/ghost_identity_hunter

2.2 Review Docker Configuration

The project includes several Docker configuration files:

  • Dockerfile - Defines the container image
  • docker-compose.yml - Defines the service configuration
  • .dockerignore - Excludes unnecessary files from build

2.3 Understand the Docker Compose Configuration

services:
  ghost-hunter:
    build: .
    image: ghost-identity-hunter:latest
    container_name: ghost-hunter
    volumes:
      - ghost_hunter_data:/home/ghosthunter/.ghost_hunter
      - ./investigations:/app/investigations
    environment:
      - PYTHONPATH=/app
      - GHOST_HUNTER_DB_PATH=/home/ghosthunter/.ghost_hunter/investigations.db
    entrypoint: ["tail", "-f", "/dev/null"]
Key Features:
  • Persistent data volume for investigation database
  • Host volume for generated reports
  • Non-root user for security
  • Environment variables for configuration

Step 3: Build and Start the Container

3.1 Build the Docker Image

# Build using docker-compose (recommended)
docker-compose build

# Or build manually
docker build -t ghost-identity-hunter:latest .

3.2 Start the Container

# Start in detached mode (background)
docker-compose up -d

# Check container status
docker-compose ps

# View logs
docker-compose logs -f ghost-hunter

3.3 Verify Container is Running

# Check if container is responsive
docker-compose exec ghost-hunter python --version

# Test the CLI
docker-compose exec ghost-hunter python src/cli.py --help

Step 4: Run Investigations

4.1 Basic Investigation Commands

# Single email investigation
docker-compose exec ghost-hunter python src/cli.py investigate --email "target@example.com"

# Multi-artifact investigation
docker-compose exec ghost-hunter python src/cli.py investigate \
  --email "target@example.com" \
  --phone "+1234567890" \
  --username "target_user" \
  --title "Comprehensive Investigation"

# Verbose investigation with custom depth
docker-compose exec ghost-hunter python src/cli.py --verbose investigate \
  --email "target@example.com" \
  --depth 3 \
  --title "Deep Investigation"

Advanced Configuration

Custom Database Location

# Create custom volume
docker volume create ghost_hunter_custom_data

# Modify docker-compose.yml to use custom volume
volumes:
  ghost_hunter_custom_data:
    external: true

Environment Variables

Add custom environment variables to docker-compose.yml:

environment:
  - PYTHONPATH=/app
  - GHOST_HUNTER_DB_PATH=/home/ghosthunter/.ghost_hunter/investigations.db
  - GHOST_HUNTER_LOG_LEVEL=DEBUG
  - HIBP_API_KEY=your_api_key_here

Custom Networks

networks:
  ghost_hunter_net:
    driver: bridge
    ipam:
      config:
        - subnet: 172.20.0.0/16

Troubleshooting

Common Issues and Solutions

Issue 1: Container Won't Start

# Check Docker daemon is running
docker info

# Check for port conflicts
docker ps -a

# Rebuild container
docker-compose down
docker-compose build --no-cache
docker-compose up -d

Issue 2: Permission Denied Errors

# Fix volume permissions
sudo chown -R $USER:$USER ./investigations

# Or run with elevated privileges (not recommended)
sudo docker-compose exec ghost-hunter python src/cli.py ...

Issue 3: Out of Disk Space

# Clean up unused Docker resources
docker system prune -a

# Check disk usage
docker system df

Issue 4: Network Connectivity Issues

# Test network connectivity from container
docker-compose exec ghost-hunter ping google.com

# Check DNS resolution
docker-compose exec ghost-hunter nslookup haveibeenpwned.com

Issue 5: Investigation Fails

# Run with verbose logging
docker-compose exec ghost-hunter python src/cli.py --verbose investigate ...

# Check container logs
docker-compose logs ghost-hunter

# Test individual modules
docker-compose exec ghost-hunter python -c "
from src.modules.breach_check import check_email_breaches
print(check_email_breaches('test@example.com'))
"

Debug Mode

For detailed debugging, modify the container entrypoint:

# Start interactive shell
docker-compose exec ghost-hunter bash

# Or run with different entrypoint
docker run -it --entrypoint bash ghost-identity-hunter:latest

Performance Optimization

Resource Limits

Add resource limits to docker-compose.yml:

services:
  ghost-hunter:
    deploy:
      resources:
        limits:
          cpus: '2.0'
          memory: 2G
        reservations:
          cpus: '1.0'
          memory: 1G

Parallel Processing

For large-scale investigations, consider running multiple containers:

# Scale the service
docker-compose up -d --scale ghost-hunter=3

# Run investigations on different containers
docker-compose exec ghost-hunter_1 python src/cli.py investigate --email "target1@example.com"
docker-compose exec ghost-hunter_2 python src/cli.py investigate --email "target2@example.com"

Security Considerations

Container Security

  • Container runs as non-root user (ghosthunter:1000)
  • No privileged access required
  • Read-only filesystem where possible
  • Limited network access

Data Protection

  • Investigation data stored in Docker volumes
  • No sensitive data in container images
  • Environment variables for API keys
  • Regular security updates

Network Security

# Restrict network access
networks:
  ghost_hunter_net:
    driver: bridge
    internal: false
    enable_ipv6: false

Backup and Recovery

Backup Investigation Data

# Backup Docker volumes
docker run --rm -v ghost_hunter_data:/data -v $(pwd):/backup \
  alpine tar czf /backup/ghost_hunter_backup.tar.gz -C /data .

# Backup host investigations directory
tar czf investigations_backup.tar.gz investigations/

Restore Investigation Data

# Restore Docker volumes
docker run --rm -v ghost_hunter_data:/data -v $(pwd):/backup \
  alpine tar xzf /backup/ghost_hunter_backup.tar.gz -C /data

# Restore host directory
tar xzf investigations_backup.tar.gz

FAQ

Q: Can I run Ghost Identity Hunter without Docker?
A: Yes, but Docker provides better isolation and reproducibility. See the local setup guide for native installation.

Q: How much disk space does Ghost Identity Hunter require?
A: Base container ~200MB, plus investigation data (varies by scope).

Q: Can I use my own HaveIBeenPwned API key?
A: Yes, set the HIBP_API_KEY environment variable in docker-compose.yml.

Q: How do I update to the latest version?
A: Run git pull and docker-compose build --no-cache, then restart.

Q: Can I run investigations in parallel?
A: Yes, scale the service or run multiple containers with different configurations.
